# Capacitor Build Pipeline

How the Next.js static export gets wrapped into iOS/Android native shells, and how to run it during development. See `PLATFORM-DECISION.md` for why Capacitor was chosen and `ARCHITECTURE.md` for the overall data flow.

## Files

- `capacitor.config.ts` — appId `com.kitto.app`, appName `LifePilot`, `webDir: 'out'`. Conditionally adds `server.url` (live-reload) when `CAP_LIVE_RELOAD_URL` is set — see below. Note `appId`/`appName` are read only by `npx cap add`; changing either does not update an existing `ios/` project (see "Bundle identifier" below).
- `ios/`, `android/` — generated by `npx cap add`, gitignored. Regenerate any time with `npx cap add ios` / `npx cap add android` (safe — no manual edits are made inside them by this pipeline).
- `.env.local` — web dev (`npm run dev`), points at `http://localhost:4000`.
- `.env.native-dev.local` — native dev builds, points at your machine's LAN IP (gitignored, per-developer, changes with network).
- `.env.production` — native prod build + prod web build, points at the real API URL (committed — public value only).

## Environment profiles

| Command | Env file used | When to use |
|---|---|---|
| `npm run dev` | `.env.local` | Browser dev. |
| `npm run build` | `.env.local` (if present) else `.env.production` | Plain static build. |
| `npm run build:native:dev` | `.env.native-dev.local` | Bake your LAN IP into a static native build (no live-reload). |
| `npm run build:native:prod` / `cap:sync:prod` | `.env.production` | Prod-flavored native build. |

## Running on a device/simulator

Targets resolve "your dev machine" differently:
- **iOS Simulator** shares the host's network stack → `localhost` works.
- **Physical iPhone** and **Android emulator/device** cannot reach the host via `localhost` → each needs the host's real **LAN IP**, and must be on the same network as the Mac.

Find your LAN IP with `npm run lan:ip` (macOS — resolves via the default route, so it is correct on Wi-Fi, wired, and tethering alike). On Windows: `ipconfig` → the active adapter's **IPv4 Address**.

It changes when you switch networks. When it does, update:
1. `.env.native-dev.local` → `NEXT_PUBLIC_API_URL`
2. `server/.env` → the LAN entry in `CORS_ORIGINS` (live-reload only), then restart the server
3. the `android:dev` script's hardcoded `CAP_LIVE_RELOAD_URL` in `package.json`

`ios:dev` reads the IP dynamically via `npm run lan:ip`, so it needs no edit.

### Physical iPhone, backend on the Mac

The backend does not run on the phone — the app talks to the Express server on your Mac over the LAN.

```bash
npm run cap:sync:dev   # bakes http://<LAN-IP>:4000 into the bundle, syncs, patches Info.plist
npx cap open ios       # then sign + run from Xcode (see "Code signing" below)
```

Or in one step: `npm run ios:device`.

The webview origin stays `capacitor://localhost` (already in `CORS_ORIGINS`), so only the API crosses the LAN. Requires `server/` running (`npm run dev` in `server/`) and Mongo up.

### Code signing (first run on a real device)

`ios/` is gitignored, so signing is configured in Xcode, not committed:

1. Xcode → **App** target → **Signing & Capabilities**
2. Check **Automatically manage signing**, pick your Team (a free Apple ID works — provisioning expires after 7 days; a paid account lasts a year)
3. Select the iPhone as the run destination and press ▶
4. On the phone: **Settings → General → VPN & Device Management** → trust the developer certificate

### Bundle identifier

`com.kitto.app`. The original `com.lifepilot.app` was already registered to another Apple account, which a Personal Team cannot claim ("Failed Registering Bundle Identifier").

It lives in **two** places that must stay in sync, because Capacitor reads `appId` only when creating the project:

- `capacitor.config.ts` → `appId` — used by a fresh `npx cap add ios`
- `ios/App/App.xcodeproj/project.pbxproj` → `PRODUCT_BUNDLE_IDENTIFIER` (two entries, Debug + Release) — what the current project actually builds with

`npx cap sync` does **not** reconcile them. If you change one, change both, or the next regenerate silently reverts to a different ID.

### App Transport Security

iOS blocks plaintext `http://` by default, which would kill every call to the LAN backend. `./scripts/patch-ios-plist.sh --local-http` adds `NSAllowsLocalNetworking` (plus `NSAllowsArbitraryLoads` as the pre-iOS 10 fallback) and `NSLocalNetworkUsageDescription`, which iOS 14+ requires before it will even prompt for local-network access.

`server.cleartext` in `capacitor.config.ts` does **not** cover this — that option is Android-only.

Builds made via `cap:sync:dev` / `ios:dev` therefore carry a relaxed ATS policy and must not be shipped. `cap:sync:prod` omits the flag and applies product keys only.

### Live-reload (hot reload on device, like the browser)

```powershell
npm run dev            # terminal A — must be reachable on the LAN for Android;
                        # if the device can't connect, try `next dev -H 0.0.0.0`
npm run ios:dev         # terminal B, iOS Simulator
npm run android:dev      # terminal B, Android emulator/device
```

Windows Firewall may prompt for a one-time inbound-rule allowance on the **private network** profile for ports 3000/4000 — allow it, or LAN devices can't reach either server.

### Static build → native IDE

```powershell
npm run ios:open       # syncs a prod-flavored build, opens Xcode (macOS only)
npm run android:open    # syncs a prod-flavored build, opens Android Studio
```

iOS builds require Xcode on macOS — not possible from a Windows machine directly. Android builds/runs work fully on Windows via Android Studio.

## Backend CORS

The Express backend only accepts listed origins (`server/src/app.ts`, `CORS_ORIGINS`). `server/.env.example` documents the full set (Next dev, `capacitor://localhost` for iOS, `http://localhost` for Android, and the LAN IP for live-reload). Update your real `server/.env` and restart the server when your LAN IP changes.

## Native plugins

`@capacitor/camera` (+ `@capacitor/filesystem`) is the **first** native plugin in this project (document scanning — `lib/documentScan/useCaptureSource.ts`). Because `ios/` and `android/` are gitignored and regenerated by `npx cap add`/`npx cap sync`, any native permission string lives OUTSIDE those directories or it is lost on the next regenerate:

- **iOS**: handled by `./scripts/patch-ios-plist.sh`, run automatically at the end of `cap:sync:dev` / `cap:sync:prod` / `ios:dev`. It is idempotent, so re-running after any regenerate is safe. Add new iOS permission strings there, never by hand-editing `Info.plist`. Only `CameraSource.Camera` is used, so no photo-library key is required.
- **Android**: `<uses-permission android:name="android.permission.CAMERA" />` must still be added to `android/app/src/main/AndroidManifest.xml` after every `npx cap add android` regenerate — there is no equivalent patch script yet.
