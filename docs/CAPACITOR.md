# Capacitor Build Pipeline

How the Next.js static export gets wrapped into iOS/Android native shells, and how to run it during development. See `PLATFORM-DECISION.md` for why Capacitor was chosen and `ARCHITECTURE.md` for the overall data flow.

## Files

- `capacitor.config.ts` — appId `com.lifepilot.app`, appName `LifePilot`, `webDir: 'out'`. Conditionally adds `server.url` (live-reload) when `CAP_LIVE_RELOAD_URL` is set — see below.
- `ios/`, `android/` — generated by `npx cap add`, gitignored. Regenerate any time with `npx cap add ios` / `npx cap add android` (safe — no manual edits are made inside them by this pipeline).
- `.env.local` — web dev (`npm run dev`), points at `http://localhost:4000`.
- `.env.native-dev.local` — native dev builds, points at your machine's LAN IP (gitignored, per-developer, changes with network).
- `.env.production` — native prod build + prod web build, points at the real API URL (committed — public value only).

## Environment profiles

| Command | Env file used | When to use |
|---|---|---|
| `npm run dev` | `.env.local` | Browser dev. |
| `npm run build` | `.env.local` (if present) else `.env.production` | Plain static build. |
| `npm run build:native:dev` | `.env.native-dev.local` | Bake your LAN IP into a static native build (no live-reload). |
| `npm run build:native:prod` / `cap:sync:prod` | `.env.production` | Prod-flavored native build. |

## Running on a device/simulator

**iOS Simulator** and **Android emulator/device** resolve "your dev machine" differently:
- iOS Simulator shares the host's network stack → `localhost` works.
- Android emulator/device cannot reach the host via `localhost` → needs the host's real **LAN IP**.

Find your LAN IP on Windows: `ipconfig` → look for the active adapter's **IPv4 Address** (e.g. `192.168.1.4`). It changes when you switch networks — update `.env.native-dev.local` and the `android:dev` script's `CAP_LIVE_RELOAD_URL` value in `package.json` when it does.

### Live-reload (hot reload on device, like the browser)

```powershell
npm run dev            # terminal A — must be reachable on the LAN for Android;
                        # if the device can't connect, try `next dev -H 0.0.0.0`
npm run ios:dev         # terminal B, iOS Simulator
npm run android:dev      # terminal B, Android emulator/device
```

Windows Firewall may prompt for a one-time inbound-rule allowance on the **private network** profile for ports 3000/4000 — allow it, or LAN devices can't reach either server.

### Static build → native IDE

```powershell
npm run ios:open       # syncs a prod-flavored build, opens Xcode (macOS only)
npm run android:open    # syncs a prod-flavored build, opens Android Studio
```

iOS builds require Xcode on macOS — not possible from a Windows machine directly. Android builds/runs work fully on Windows via Android Studio.

## Backend CORS

The Express backend only accepts listed origins (`server/src/app.ts`, `CORS_ORIGINS`). `server/.env.example` documents the full set (Next dev, `capacitor://localhost` for iOS, `http://localhost` for Android, and the LAN IP for live-reload). Update your real `server/.env` and restart the server when your LAN IP changes.

## Native plugins

`@capacitor/camera` (+ `@capacitor/filesystem`) is the **first** native plugin in this project (document scanning — `components/scan/CameraCapture.tsx`). Because `ios/` and `android/` are gitignored and regenerated by `npx cap add`/`npx cap sync`, any native permission string lives OUTSIDE those directories or it is lost on the next regenerate:

- **iOS**: `NSCameraUsageDescription` must be added to `ios/App/App/Info.plist` after every `npx cap add ios` / a from-scratch regenerate. There is no committed patch script yet — until one exists, add it manually each time:
  ```xml
  <key>NSCameraUsageDescription</key>
  <string>Mo uses your camera to scan documents so it can pull out bills, appointments, and deadlines.</string>
  ```
- **Android**: `<uses-permission android:name="android.permission.CAMERA" />` must be added to `android/app/src/main/AndroidManifest.xml` after every `npx cap add android` regenerate, same manual-reapply caveat.

If this project adds more native plugins later, promote this into a real post-`cap sync` patch script (e.g. via `npx cap sync` hooks or a small Node script run after `cap:sync:*`) rather than continuing to hand-edit generated files.
