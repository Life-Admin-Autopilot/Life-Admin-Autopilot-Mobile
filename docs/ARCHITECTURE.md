# Architecture — Mo V2 (Next.js + Capacitor)

The target shape of the rebuilt app. Read alongside `PORTING-GUIDE.md` (what carries over) and `AGENTS.md` (the rules).

## The big picture

```
┌──────────────────────────────────────────────┐
│  Next.js app (App Router, static export SPA)  │
│  React · TanStack Query · Zustand · Zod · RHF │
│  Tailwind + shadcn/ui primitives              │
└───────────────┬──────────────────────────────┘
                │ next build → static HTML/JS/CSS in /out
        ┌───────┴────────────────┬─────────────────────┐
        ▼                        ▼                     ▼
┌──────────────┐        ┌──────────────┐      ┌──────────────────┐
│ iOS (Capacitor)       │ Android (Capacitor)  │  Web / PWA        │
│ WKWebView +  │        │ WebView +    │      │  (browser)        │
│ native plugins        │ native plugins│      │  + PWABuilder TWA │
└──────┬───────┘        └──────┬───────┘      └─────────┬────────┘
       │   native: APNs push, background audio, secure store         │
       └────────────── all call over HTTP ──────────────────────────┘
                                  │  NEXT_PUBLIC_API_URL
                                  ▼
                ┌──────────────────────────────────┐
                │  server/  — Express + MongoDB      │
                │  JWT auth · Zod · Gemini · Resend  │
                └──────────────────────────────────┘
```

Key fact: **the phone runs the static web bundle inside a native shell.** There is no Node server on-device. All dynamic behavior is client-side + the separate Express backend. This is why Next runs in `output: 'export'` mode.

## Data flow

1. A component calls a hook from `queries/` (e.g. `useOpenTasks()`).
2. The hook calls an endpoint module in `lib/api/` which calls `lib/api/client.ts`.
3. `client.ts` adds the auth token, hits `NEXT_PUBLIC_API_URL` (the Express backend), and on 401 refreshes once and retries.
4. TanStack Query caches by keys from `queries/keys.ts`; mutations reconcile the cache (v1 already built optimistic insertion + tool-result cache sync — reuse that logic).

Auth differs from v1: instead of Zustand + `expo-secure-store`, prefer **httpOnly refresh cookie + in-memory access token** (or Capacitor Secure Storage on native). See PORTING-GUIDE for the `lib/auth/sessionStore.ts` rebuild note.

## Deployment path (incremental — don't do it all at once)

1. **Web/PWA first.** `next build` → deploy `out/` to Vercel/Netlify as a normal site + PWA manifest + service worker (offline). Fastest feedback, zero native.
2. **Android via PWABuilder TWA.** PWABuilder packages the PWA as a Trusted Web Activity — runs real Chrome, full web push, passes Play review easily. Cheap Android presence.
3. **iOS (and richer Android) via Capacitor.** Wrap the same build: `npx cap add ios android`, add `@capacitor/push-notifications` (native APNs/FCM), add a native audio-recorder plugin for background capture. This is where native push + background audio become real. (Don't use PWABuilder's iOS wrapper — its WKWebView can't do Web Push and risks guideline-4.2 rejection; Capacitor's native plugins are the fix. See `PLATFORM-DECISION.md`.) The base pipeline (packages, `capacitor.config.ts`, env profiles, dev scripts) is already wired up — see `CAPACITOR.md` for day-to-day usage.

## Backend (`server/`)

Express + MongoDB (Mongoose), JWT (access + refresh), Zod validation, Pino logging. AI orchestration under `server/src/modules/ai/` (Gemini provider, tool runner, conversation service, voice transcription, quota). Routes under `server/src/routes/` (`auth.*`, `me.*` for tasks/voiceNotes/clarifications/deviceTokens/billing, `health`). **It's client-agnostic** — the web client talks to it exactly as the RN client did. Config via `server/.env` (copy from `.env.example`, generate fresh secrets).
